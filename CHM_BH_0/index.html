Appendix to Appendix A: Defect of BH Matrices from Butson Home

created: 2022-07-28

updated: 2023-02-22 by W. Bruzda

Not every file in the repository is listed on this page. The collection grows faster than these tables – for the complete set, browse the repository directly.

In order to save space, integer matrices in a LOG-form are encoded in plain-text files (the core together with surrounding 2N-1 zeros in the first row and the first column), where overdecadic numbers are replaced by single ASCII characters. Decoding procedure is straightforward, but in some cases the total number of arrays makes it impossible to process them in a single run. All procedures are designed for *NIX system. When working in m$ OS, currently (2022-07-26) it is not easy to combine w7, MinGW, and Octave-5.1.0.0 (CLI) into a "one-script-to-run-and-forget" environment:

C:\MinGW\msys\1.0\bin> .\bash.exe
bash.exe"-3.1$ ./BHr.out SPLIT_FILE_ax # fatality...

Possible Linux issue:

QStandardPaths: XDG_RUNTIME_DIR not set, defaulting to '/DIRECTORY'
→
$ export XDG_RUNTIME_DIR=DIRECTORY
$ export RUNLEVEL=3
$ source .bashrc

Actually, the main purpose was to calculate the linear entropy of all Butsons (for a project concerning k-unitary CHM... – under construction). Later, slightly modified scripts were reused to calculate the defects.

Download appropriate zip from Butson Home and follow the steps:

1. Linear Entropy (or Entangling Power)

Only squared-dimension matries are of interest. All Butsons are normalized to be unitary: B → B/√{N} for N=9 or N=16.

There is one problematic (squared-dim.) file: BH-16-4.txt (1'786'763 entries) and q = 4. Before calculating SL the file must be split:

  1. split file:
    $ split BH-16-4.txt -l 100000 SPLIT_FILE && shred -zuv BH-16-4.txt
  2. this produces several files, each with 100000 lines:
    SPLIT_FILEaa
    SPLIT_FILEab
    ...
    SPLIT_FILEar
  3. ./get_SL.sh SPLIT_FILEax SL_BH_NN_qq_ax.txt
    script get_SL.sh uses another one: b2m.sh which extracts n-th line from a raw BH-file: $ ./b2m.sh BH-16-14.txt 4 123
  4. check:
    $ wc -l SL_BH_NN_qq_ax.txt
    should yield 100000 (lines)
    or RT inspection:
    $ tail -F FILE

alternative and much faster method:

  1. prepare M-file (using chunks of  ≈10000 lines) with a simple C-script:
    > cc BHrc.c -lm -o BHrc.ELF
  2. > BHrc.ELF SPLIT_FILEax 4 CHUNK_SIZE # watch 4 = q = BUTSON parameter!

BHrc.ELF creates (a large) OCTAVE_OUTPUT.m file, which can be handled very quickly on Intel(R) Core(TM) i7-4770 CPU @ 3.40GHz with 16+GB of RAM;

  1. >> clear all; B=OCTAVE_INPUT; B_SIZE=size(B,2); # this might take a while...
    >> diary on; diary SL_BH_NN_qq_ax.txt; for k=2:B_SIZE; disp(sprintf("%g\t%g", SL(R(B{k})), SL(T(B{k})))); end; diary off
    >> exit
  2. clean SL_BH_NN_qq_ax.txt file (remove the first and the last line), remove diary (if exists), and remove OCTAVE_OUTPUT.m (to save space it is good to dos2unix all files)

When all SPLIT_FILEax are done, merge all SL_BH_NN_qq_ax.txt into a single file: SL_BH_NN_qq.txt to be supplied for gnuplot.

Dimension N=9 is much simpler, it is enough to apply BHrc.c and get_SL.sh scripts for several files.

2. Defect of BH

This time, there are two problematic files: BH-16-4.txt (1'786'763 entries) and BH-12-12.txt (4'497'733 entries). Moreover, the calculation of defect takes much longer than calculation of "linear entropy".

The procedure is similar, for small files do:

  1. download BH-NN-qq.txt
  2. $ ./BHrc BB-NN-qq.txt q BH_CARDINAILTY
  3. $ octave get_defect.m > BB-NN-qq.txt
  4. $ ./count_isolated.sh defect_BH_NN_qq.txt # this number goes to the table in results

while, for big files, apply the two-step mechanism:

  1. splitting...
  2. $ octave... # ---> get_defect.m
  3. cleaning...

Cardinality check:

  1. $ wc -l defect_BH* # should return: 6815584 (this excludes N=2, 3, 5 and 11)

Finally, perform some random tests (independently calculated values of defect must match!)

  1. $ ./check_defect.sh BH-14-4.txt 4 123 defect_BH_14_4.txt # manual check
  2. $ ./test_defect.sh BH-12-12.txt defect_12_12.txt 12 100000 # run overnight...
