Appendix E: Block-Circulant CHM

created: 2026-09-13

updated: 2026-09-13 by W. Bruzda

Not every file in the repository is listed on this page. The collection grows faster than these tables – for the complete set, browse the repository directly.

The matrices collected here come from "Block-Circulant Complex Hadamard Matrices" [175]. They are numerical, not analytic: each one is a solution of the unitarity constraints imposed on a block-circulant pattern, found with fsolve and refined until the residual reaches machine precision.

Two sequences are solved here:

  • LN – only for N = 3 + 4k, k = 0, 1, 2, ...
  • VN – for any N = 6, 7, 8, ...

Their interest is that almost every solution turns out to be isolated (defect d = 0) and not of Butson type. For LN one obtains isolated solutions only; for VN other defects occur as well. Since the sequences can be run in essentially any dimension, they provide numerical support for the conjecture that isolated complex Hadamard matrices exist in every dimension – a question left open by the analytic constructions, which supply isolated examples only in special dimensions (Fourier Fp for prime p, S6, and a handful of others).

For the initial dimensions 11–16 each run returns different values of the parameters; whether the resulting matrices are inequivalent is not known.

Filename scheme↑

Every file stores the phase matrix A, so that H = exp(2πi·A) is the complex Hadamard matrix itself:

LH_N_d_L.dat    block-circulant, sequence L
VH_N_d_L.dat    block-circulant, sequence V

        N = size(H)
        d = defect(H)
        L = #Λ(H), cardinality of the Haagerup set

Both invariants are expensive, so they are recorded only while that is affordable, and the name degrades in a fixed way:

N ≤  40      LH_N_d_L.dat      both invariants
N ≤  60      LH_N_d.dat        #Λ too slow to compute
N >  60      LH_N.dat          both too slow to compute

A trailing letter distinguishes different solutions that share the same invariants (VH_14_0_687A, ...B, ...); a trailing word records a property worth keeping (_persymmetric, _BH).

Files taken over from the earlier LN/ and VN/ directories keep the whole Octave workspace they were saved with (H, defect, F_norm, is_convergent, ...) in addition to the matrix; the newer ones store A alone.

Scripts↑

The two generators write a ready-to-run Octave M-file for a given dimension; running it solves the system and saves the solution under the name above.

$ ./BC_L.sh 11          # writes LH_11.m
$ ./C_V.sh 10           # writes VH_10.m

octave:1> H = LH_11;    # solves, then saves LH_11_0_191.dat

bc_name.m builds the file name and is the only helper the generated M-files need; it calls ud.m for the defect.

LN works only for N = 3 + 4k; the number of parameters is (N−1)/2. For N > 55 the invariants take too long and the name is shortened automatically.
